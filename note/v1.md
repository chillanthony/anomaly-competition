# v1 开发路线

目标：在 `dataset-phase-1` 上跑通「故障检测 + 根因定位 + 分类」，
新代码全部放在 `baseline/v1/`，不动官方 `baseline/bian` 与 `aiops_challenge_2026/`。

## 阶段 1：检测器（当前优先级最高）

现状：`baseline/bian/anomaly_detector/five_sigma.py` 在 phase-1 全量上
只输出**一条**预测，区间 2026-08-21 → 2026-09-02（横跨 11 天），
Dice ≈ 0.001 ≪ 0.4 → 零匹配 → AD=0 → 漏报门控把 RCA/Major/Minor 一起清零 → 总分 0。
比 sample 基线的 28.22 还差。必须先修这个。

修复顺序：

1. **序列 key 补维度**：`interface_metrics` 要带 `interface_id`，
   `routing_metrics` 要带 `metric_name` + `label`。
   现在不同接口/不同路由指标被混进同一条序列，均值和方差都是错的。
2. **重写事件合并**：合并只在单个 `(node, metric)` 序列内部做，
   并加最长事件时长上限（先取 30 min）与最小支撑点过滤。
   跨序列合并是那条 11 天事件的直接原因。
3. **换基线**：丢点首 20% 的 in-sample 均值/标准差，改成滚动中位数 + MAD，
   再叠加「同 role 跨 region 节点对比」，减少对首段数据是否干净的依赖。
4. **收敛 magnitude**：`|v-mean|/max(std,1e-12)` 在平坦序列上会爆掉，
   用来排序 Top-5 会把真正的根因挤出去，需要裁剪或改用稳健尺度。

检测策略基调：宁可多报不可漏报（漏报代价 ≈ 300 倍误报），
但**同一故障不重复报**——重复上报是纯损失（Dice 一对一匹配消耗掉名额）。

## 阶段 2：补数据源

- NetFlow（每 region 22.5 GB，必须 `usecols` + `chunksize` 流式读）
- FRR syslog 事件
- 两者目前都被 `five_sigma.py` 直接 `continue` 跳过，
  但 `tools/run_phase1_baseline.py` 又要求这些文件存在 —— 要求了不读的文件。

## 阶段 3：根因定位（RCA）

- 官方 `baseline/bian/config/topology.json` 是手工造的（单城市模板复制 8 份、无向图），
  必须从 NetFlow / traffic_flow 数据反推真实拓扑。
- 注意枚举空间：8 region × 10 role = 80 个 `network_element_id`。
- `monitor-vm` 是 schema 合法值但**不是根因候选**，要自己排除。
- Top-5 内 `network_element_id` 重复 → 整条记录 0 分。

## 阶段 4：分类

- 5 个大类 × 28 个小类。
- 规则优先，7B 模型（DeepSeek-R1-Distill-Qwen-7B）做仲裁。
- 无效枚举线上直接 0 分，必须对枚举表做校验。

## 关键约束

- 评分：`Total = 40·AD + 40·RCA + 10·Major + 10·Minor`
- 时间精度：`S_time = max(0, 1 - (Δs+Δe)/360)`，即 `T_max = 180 s`
- 除 NetFlow 外所有数据 5 分钟采样，而 `T_max = 180 s` **短于一个采样间隔** ——
  区间端点只能靠插值/事件对齐来逼近。
